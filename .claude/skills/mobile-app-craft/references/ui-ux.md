# UI／UX 原則

## 資訊架構
- 依「使用者想做什麼」分組，而不是依技術分類。底部主分頁 3–5 個，每個分頁內 2–4 個子功能用分段切換（segmented control）。
- 首頁：先摘要再細節。首屏給「今天/現在最重要的一件事」＋一個主要行動；接著是「快速入口」格（4×2 圖示＋兩字標籤），把最常用的功能一鍵直達；其餘內容做成可收合卡片。
- 每頁有大標題＋一行副標（說明這頁做什麼），長內容的頁面附「這頁怎麼看？」收合說明。
- 切換分頁要記住各頁捲動位置；舊網址錨點要能對應到新結構。
- 有「範例資料／示範模式」時，在每頁標題下常駐標記，避免誤認為個人結果。
- 長輩友善：字級設定（1／1.15／1.3／1.45 倍＋粗體）、簡易模式（只留最常用 3 個分頁與大按鈕）。

## 版面
- 單欄、最寬 600px、左右 16px 安全邊距；卡片圓角 16–22px，卡片之間 12–16px。
- 底部分頁列：往下捲時收起、往上捲或到底時出現，絕不遮住內容；底部固定元素都要避開分頁列與 safe-area。
- 觸控目標至少 44×44px；主要按鈕放拇指好按的位置。
- 標籤與內文分行（標題在上、內文在下），大字級時才不會擠成多行。
- 任何狀態（吉凶、選取、分數）不可只靠顏色，要有文字或圖示。

## 美術
- 先定主題：背景插畫（日／夜兩版，同構圖不同時間）＋半透明卡片＋細金邊或主題色描邊；標題用襯線體（宋體）增加質感。
- 色彩用 CSS 變數成組定義（bg、card、ink、muted、tint、line、glass…），深色版另一組；兩組都要過對比檢查。
- 一致的裝飾語彙（例如星芒、細線、菱形分隔），不要混搭多種風格。
- 使用者提供參考圖時，以參考圖的構圖與配色為準，用向量（SVG/CSS）重現以保持清晰與輕量；使用者提供點陣素材則壓成 JPEG（品質 80）後使用。

## 文案
- 白話、短句、具體動詞；不恐嚇、不保證；專業術語附括號白話。
- 錯誤訊息說明原因與下一步。

## 使用者偏好（持續累積）
- 重視「直觀」：第一次使用不需說明也知道下一步。
- 重視動效質感：開場與核心互動要有儀式感、精緻，但日常導覽要快。
- 不要多餘的裝飾元素（例如不明意義的黑點、紅色印章）；每個元素都要有意義。
- 分享圖卡不放網址、留白要少、字體要專業（宋體）。
- 更新後要彈出「更新內容」（版本號＋編號清單＋立即更新／稍後更新）。
- 要引導用網頁開啟的使用者加到主畫面，Android 一鍵安裝、iOS 圖解步驟。
- 專業內容（命理、醫療、金融等）一律「白話優先、術語小字附註」：使用者看完就要懂，不需要再去問 AI。結構參考：一句話結論 → 關鍵字 → 白話說明 → 條列特質 → 對照表；並附「名詞小辭典」。
- 要「賣給一般人」的內容（報告、解讀）不能是資料條列：用專業者親筆寫給客人的口吻，有開場與結語、每章先說明依據、段落之間有承接、結論後給具體建議；用多組不同資料產生後逐篇讀過，檢查語病與重複。
